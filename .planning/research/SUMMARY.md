## Table Stakes Features

Every user expects these. Missing any one causes immediate churn.

- Text food search — USDA FoodData Central; top 10 results; debounced (not per-keystroke)
- Barcode scan — camera-based UPC/EAN-13; look up by gtin_upc in usda_foods cache
- Recent foods — last 10–20 foods logged; one-tap re-add
- Favorites / saved foods — user-starred foods for permanent quick-access
- Custom food creation — name + macros manually for homemade meals or missing entries
- Serving size adjustment — stepper (0.5x–2x) plus gram-level input
- Meal slots — Breakfast / Lunch / Dinner / Snack
- Edit and delete logged items — absence causes immediate rage churn
- Today dashboard — macro progress, meals summary, "remaining" framing (not deficit)
- Day navigation — date-strip to past days
- Weekly macro trend — 7-day chart (protein, fiber, GL)
- Weight logging + trend — 7-day rolling average only (never raw daily)
- Goal tracking UI — floor targets for protein/fiber; ceiling targets for GL/sugar

## PCOS Differentiators

These are Bloom's reason to exist. No general nutrition app gets any of these right.

- **Glycemic Load as a first-class daily metric** — GL per food item, daily total vs. ceiling, GL timeline by meal. GL beats GI because it accounts for serving size.
- **Insulin Balance Score** — composite 0–100 score synthesizing protein adequacy, fiber adequacy, GL vs. ceiling, added sugar, and P:C ratio. Always shown with a 1–2 sentence narrative. Generated by Claude, cached per cycle phase.
- **Protein-to-Carb ratio tracking** — displayed on diary totals; 1:1 to 1:1.5 target blunts post-meal insulin spikes. No competitor surfaces this ratio.
- **Cycle-phase nutrition context** — AI targets shift with phase (tighter GL ceiling in luteal, higher protein floor). Not a fertility tracker; no ovulation prediction.
- **Symptom correlation** — daily symptom check-in (energy, mood, sleep, bloating, skin); weekly correlation insight via Claude.
- **PCOS-friendly food tagging** — qualitative chip on search results; anti-inflammatory filter on recipe browser.
- **Coach read-only access** — shareable invite token; B2B2C growth lever.

## Architecture Decisions

**Supabase schema:**
- Denormalize macros into `food_logs` at write time — never FK to a foods table. Historical accuracy requires preserving exact values at log time.
- Shared `usda_foods` cache table keyed by `fdc_id`, with `gtin_upc` index. No RLS (public cache); writes via Edge Function only. 30-day TTL.
- `ai_daily_targets` caches Claude output per user per cycle phase. Regenerate only on: first login, profile change, or cycle phase change.
- `coach_invites` join table — invite-token model. RLS checks `status = 'accepted'` on every coach read.
- Profiles created by `on_auth_user_created` trigger — client never INSERTs into profiles.

**RLS pattern:** `(select auth.uid()) = user_id` (parenthesized form — evaluated once per query, not per row) on all user-owned tables.

**GL calculation:** Local TypeScript lookup table (`src/lib/gl.ts`) mapping `fdc_id` and USDA food categories to GI values from the Sydney University GI database. Formula: `GL = GI × (carbs_g - fiber_g) / 100`. GL displays as "—" when GI unavailable — never 0.

**Claude invocation:** Edge Function only — API key never in Vite env files. Cache in `ai_daily_targets`. Estimated ~$0.002–$0.01/user/month.

**Routing:** Two layout stacks (`AuthLayout`, `AppLayout`). Guards: `RequireAuth` and `RequireProfile`. Food logging routes (`/log/*`) outside `AppLayout` — no tab bar during logging.

**PWA cache rules:** App shell = CacheFirst; USDA API = StaleWhileRevalidate (7-day TTL); Supabase reads = NetworkFirst; Supabase writes = NetworkOnly + BackgroundSync; Claude API = NetworkOnly (never cache).

## Critical Blockers

Resolve these before writing any feature code.

1. **RLS on every table from migration 1** — enable RLS and write correct policies in the same migration. Cycle and symptom data leaking is a harm event.
2. **Supabase singleton client** — one module-level instance only. Multiple instantiations cause JWT refresh races and spontaneous logouts.
3. **GL data architecture settled before schema** — USDA has no GI/GL. Commit to the local GI table approach before writing `food_logs` schema.
4. **Claude invocation via Edge Function only** — API key must never appear in Vite env files (Vite bundles them into client JS).
5. **AI guardrails in system prompt before any AI ships** — prohibit medical diagnosis, supplement dosages, drug interactions. Cannot be retrofitted.
6. **iOS Safari PWA limitations acknowledged** — build habit loops through in-app prompts, not push notifications.
7. **Data deletion workflow before production data is stored** — GDPR and FTC Health Breach Notification Rule both apply.

## Top Pitfalls to Avoid

| Pitfall | Prevention |
|---------|-----------|
| RLS `using (true)` placeholder left in production | Verify with curl + anon key before any phase ships |
| USDA rate limit (1,000 req/hr) hit during food search | Debounce 400ms; check usda_foods cache first |
| Claude called on every dashboard load | Cache in ai_daily_targets; regenerate on phase change only |
| Claude hallucinating medical advice | System prompt prohibits it; Haiku pre-screen; XML input wrapping |
| Barcode scan returns nothing (USDA branded coverage is thin) | Fallback to Open Food Facts; manual entry is first-class |
| Weight chart showing daily decimal fluctuations | 7-day rolling average only; raw daily weight harms PCOS users |
| Calorie restriction framing | Frame all metrics around adequacy, never deficit |
| Service-role key in Vite env file | Service-role in Edge Functions only; anon key on client |
| TypeScript DB types drifting from schema | Run `supabase gen types typescript` in CI on every migration |

## Open Questions

1. **GI database licensing** — Sydney University GI database commercial licensing status unclear. What fallback covers 200–300 common PCOS foods?
2. **Open Food Facts as barcode fallback** — use it (with accuracy disclaimer) or accept barcode gaps at launch?
3. **HIPAA exposure** — likely not a covered entity, but requires healthcare attorney confirmation before storing production data.
4. **Phase-based macro fallback values** — what static values when Claude is unavailable? Needed for graceful degradation.
5. **Anti-inflammatory food tagging criteria** — which foods get the "PCOS-friendly" chip, and who maintains the list?
6. **EU data residency** — if EU users expected, Supabase project must be created in EU region from the start.
