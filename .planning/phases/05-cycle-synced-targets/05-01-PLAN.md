## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | buildUserPrompt cycle_day computation | mitigate | cycle_day is computed server-side from profile.last_period_date (fetched via RLS-enforced query) — user cannot inject a different phase by manipulating the request body |
| T-05-02 | Information Disclosure | cycle_phase stored in ai_daily_targets | accept | cycle_phase is coarse ("luteal") not a specific date; RLS policy ai_targets_select_own restricts reads to the row owner |
| T-05-03 | Spoofing | last_period_date user input | accept | Date is stored in user-owned profiles row (RLS-enforced); worst-case a user sets a wrong date affecting only their own targets |
| T-05-04 | Denial of Service | PROMPT_VERSION=2 triggers mass regeneration | accept | Regeneration is per-user at first load; stale check fires once then caches for 5 min (staleTime: 5 * 60 * 1000) |
| T-05-SC | Tampering | No new npm/pip installs in this plan | accept | No new package manager installs; Edge Function uses existing esm.sh imports already in production |
</threat_model>
