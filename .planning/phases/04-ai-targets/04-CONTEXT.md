# Phase 4: AI Targets — Claude Edge Function + Insulin Balance - Context

**Gathered:** 2026-05-18
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 4 delivers the AI backbone of the app:
- A Supabase Edge Function (`generate-targets`) that calls Claude API, generates personalized macro targets + Insulin Balance score, and writes them to `ai_daily_targets`
- A new DB migration adding `insulin_score smallint` column to `ai_daily_targets` (the 0–100 score needs a queryable integer column separate from the jsonb basis)
- `useAITargets` React hook (Phase 04-02) that checks the cache and calls the Edge Function only when needed
- Dashboard wired to display real AI targets and Insulin Balance score (Phase 04-02)
- Fallback to `STATIC_TARGETS` when the Edge Function is unavailable (Phase 04-02)

**What 04-01 delivers:** Edge Function + migration only.
**What 04-02 delivers:** client hook + dashboard wiring + fallback.

</domain>

<decisions>
## Implementation Decisions

### Prompt Input Scope
- **D-01: Profile-only input** — The Edge Function reads `profiles` row for the requesting user (pcos_type, goals[], age, height_cm, current_weight_kg, goal_weight_kg). Does NOT read food_logs or symptom_logs in Phase 4. Targets are profile-level personalization, not real-time daily adjustments. Food/symptom context is a Phase 5+ enhancement.

### Claude Output Format
- **D-02: Structured JSON only** — Claude is prompted to return ONLY a valid JSON object (no markdown, no prose wrapping). The system prompt specifies exact field names. On JSON parse failure, the Edge Function returns HTTP 500 (client falls back to static targets). No regex parsing.
- **D-03: JSON output schema** — Claude returns:
  ```json
  {
    "protein_g": 125,
    "fiber_g": 32,
    "gl_target": 90,
    "added_sugar_g": 20,
    "calorie_min": 1600,
    "calorie_max": 1800,
    "pc_ratio_target": 0.35,
    "insulin_score": 72,
    "narrative": "1–2 sentence plain-language explanation",
    "key_factors": ["insulin_resistance_type", "weight_loss_goal", "high_protein_priority"]
  }
  ```
- **D-04: Model** — `claude-sonnet-4-6` (matches CLAUDE.md tech stack). Temperature 0 for reproducible outputs.

### System Prompt Guardrails (AI-05)
- **D-05: Hard prohibitions in system prompt** — Must include explicit instructions that Claude may NOT: provide medical diagnoses, recommend specific supplements or dosages, give drug interaction advice, or suggest anything that should be evaluated by a healthcare provider. Targets are nutritional guidance only, framed as adequacy (not deficit).
- **D-06: PCOS framing** — System prompt positions Claude as a PCOS nutrition specialist generating evidence-based macro targets to support insulin sensitivity. Framing: "Your role is to generate daily macro targets that support insulin balance for a woman with PCOS."

### Insulin Balance Score
- **D-07: Claude generates the score** — The 0–100 Insulin Balance score is generated by Claude as a profile-level assessment (how well the recommended targets support insulin balance for this user's specific profile). It is NOT a real-time score of today's food choices — that would violate the cache-on-profile-change requirement.
- **D-08: DB column** — Add `insulin_score smallint` column to `ai_daily_targets` via a new migration (do not use jsonb for the score — needs to be queryable as an integer). The existing `insulin_score_basis jsonb` stores `{ key_factors: string[] }`.
- **D-09: Score interpretation** — Higher = better insulin balance potential for this profile. 0–40: high insulin resistance risk profile; 41–70: moderate; 71–100: optimized.

### Caching Strategy
- **D-10: Edge Function is stateless (always generates)** — The Edge Function never checks whether a fresh cache row exists. It always calls Claude and inserts a new `ai_daily_targets` row. The intelligence about WHEN to call the function lives in the Phase 04-02 client hook.
- **D-11: Cache check logic (for Phase 04-02 reference)** — The `useAITargets` hook should call the Edge Function only if: (a) no row exists for this user, or (b) `profiles.updated_at > latest ai_daily_targets.generated_at`, or (c) `prompt_version` in the latest row is stale (< current app prompt version).
- **D-12: prompt_version** — Start at `1`. Increment in the Edge Function's source when the system prompt changes. Stored in the `ai_daily_targets` row to enable cache invalidation on prompt upgrades.

### Edge Function Architecture
- **D-13: Request/response shape** — POST with JWT in `Authorization` header (same pattern as `delete-account` and `usda-search`). No request body required — profile is fetched from DB using the JWT's user_id. Response: `{ protein_g, fiber_g, gl_target, added_sugar_g, calorie_min, calorie_max, pc_ratio_target, insulin_score, narrative, generated_at }`.
- **D-14: User JWT for DB operations** — Use the user's JWT (not service role) to fetch profile and insert the new row. RLS on `ai_daily_targets` already has INSERT policy for authenticated users (`with check ((select auth.uid()) = user_id)`). Service role not needed.
- **D-15: ANTHROPIC_API_KEY** — Stored in Supabase Edge Function secrets as `ANTHROPIC_API_KEY`. Accessed via `Deno.env.get('ANTHROPIC_API_KEY')`. Never exposed to Vite build.
- **D-16: Anthropic SDK** — Use `https://esm.sh/@anthropic-ai/sdk` (same CDN pattern as existing `esm.sh/@supabase/supabase-js@2` imports). Import at top of function.

### Error Handling
- **D-17: HTTP 500 on Claude failure** — If Claude API call fails or returns unparseable JSON, the Edge Function returns `{ error: "generation_failed", message: ... }` with HTTP 500. The client hook catches 5xx and falls back to `STATIC_TARGETS` (Phase 04-02).
- **D-18: Profile not found** — If the user has no profile row, return HTTP 400 `{ error: "profile_required" }`. Edge Function does not generate targets without a complete profile.

### Claude's Discretion
- All areas delegated by user. All decisions above are Claude's choices optimized for correctness, PCOS domain fit, and codebase consistency.

</decisions>

<specifics>
## Specific Ideas

- The Edge Function function name in Supabase is `generate-targets` (matches `supabase/functions/generate-targets/index.ts`)
- JSON parse validation: use `JSON.parse()` wrapped in try/catch; validate that all required fields are present and numeric; reject if any are missing/null
- The `key_factors` array from Claude's JSON goes directly into `insulin_score_basis jsonb` as `{ key_factors: [...] }`
- System prompt should include a concrete example of valid JSON output so Claude knows the exact format expected

</specifics>
