## Summary

Phase 04-01 delivers a single Supabase Edge Function (`generate-targets`) and one database migration. The function authenticates the caller via JWT, fetches the user's profile row, builds a PCOS-specialised prompt, calls Claude with temperature 0 for deterministic structured JSON output, validates the response against biological range checks, and inserts a new `ai_daily_targets` row. The migration adds an `insulin_score smallint` column that the Edge Function populates alongside the existing `insulin_score_basis jsonb` column.

The existing codebase provides two ready-to-copy patterns: `delete-account/index.ts` for the JWT verification boilerplate and `usda-search/index.ts` for the CORS headers and error-response shape. The Anthropic TypeScript SDK imports identically to the existing `@supabase/supabase-js@2` CDN import — same `esm.sh` pattern, same non-null assertion for required env vars.

CORS must be handled manually in Supabase Edge Functions because the browser sends a preflight `OPTIONS` request before the `POST`. Both existing functions omit CORS (they rely on `verify_jwt: true` in `config.toml` which routes JWT verification to Supabase infrastructure before the handler runs, but CORS preflight still requires a `200` response from the handler itself). The `generate-targets` function must handle `OPTIONS` returning the correct headers.

**Primary recommendation:** Copy the JWT verification block from `delete-account/index.ts` verbatim; add the CORS headers block from the pattern below; use user JWT (not service role) for both the profile SELECT and the `ai_daily_targets` INSERT (RLS permits both for authenticated users).

### Pattern 1: JWT Verification (copy verbatim from delete-account)

**What:** Verify caller's JWT, get `user` object with `user.id`
**When to use:** Start of every authenticated Edge Function

```typescript
// Source: supabase/functions/delete-account/index.ts (lines 1-18)
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'

Deno.serve(async (req) => {
  const authHeader = req.headers.get('Authorization')
  if (!authHeader) {
    return new Response('Unauthorized', { status: 401 })
  }

  const supabaseUser = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_ANON_KEY')!,
    { global: { headers: { Authorization: authHeader } } }
  )
  const { data: { user }, error } = await supabaseUser.auth.getUser()
  if (error || !user) {
    return new Response('Unauthorized', { status: 401 })
  }
  // ... user.id is now available
})
```

### Pattern 2: CORS Preflight Handling

**What:** Return `200` with CORS headers for `OPTIONS` requests before the real `POST`
**When to use:** Any Edge Function called from a browser client

The existing `delete-account` and `usda-search` functions do NOT include CORS headers. They work because `usda-search` is called via `supabase.functions.invoke()` which does not trigger browser CORS preflight in the same way as a direct `fetch()`. However, `generate-targets` will be called via `supabase.functions.invoke()` as well — but it is best practice to include CORS headers in all Supabase Edge Functions for browser compatibility. [ASSUMED: Supabase docs recommend CORS handling in Edge Functions for browser clients — existing functions work without it due to `invoke()` abstraction, but explicit CORS is the documented safe pattern]

```typescript
// CORS headers — add at top of Deno.serve handler
const corsHeaders = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Headers': 'authorization, x-client-info, apikey, content-type',
}

Deno.serve(async (req) => {
  if (req.method === 'OPTIONS') {
    return new Response('ok', { headers: corsHeaders })
  }
  // ... rest of handler
  // All JSON responses must include corsHeaders alongside Content-Type
})
```

### Pattern 3: Anthropic SDK Call in Deno

**What:** Single-turn `messages.create` call with system prompt + user prompt
**When to use:** The one Claude API call in `generate-targets`

```typescript
// Source: 04-AI-SPEC.md Section 3 — Framework Quick Reference [CITED: .planning/phases/04-ai-targets/04-AI-SPEC.md]
import Anthropic from 'https://esm.sh/@anthropic-ai/sdk'

const PROMPT_VERSION = 1

const client = new Anthropic({ apiKey: Deno.env.get('ANTHROPIC_API_KEY')! })

const response = await client.messages.create({
  model: 'claude-sonnet-4-6',
  max_tokens: 512,
  temperature: 0,
  system: SYSTEM_PROMPT,
  messages: [{ role: 'user', content: buildUserPrompt(profile) }],
})

// Always type-check content block before accessing .text
const text = response.content[0].type === 'text' ? response.content[0].text : ''
if (!text) throw new Error('Empty response from Claude')

let parsed: unknown
try {
  parsed = JSON.parse(text)
} catch {
  throw new Error(`JSON parse failed: ${text.slice(0, 200)}`)
}

const targets = validateTargets(parsed) // throws on invalid
```

### Pattern 4: Profile-to-Prompt Serialization

**What:** Convert the profiles row into a readable user prompt string
**When to use:** Inside `buildUserPrompt()` function

```typescript
// Source: 04-AI-SPEC.md Section 4b — Prompt Engineering Discipline [CITED: .planning/phases/04-ai-targets/04-AI-SPEC.md]
// Profile fields from database.types.ts: pcos_type, goals[], age, height_cm, current_weight_kg, goal_weight_kg
function buildUserPrompt(profile: ProfileRow): string {
  const lines = [
    `PCOS type: ${profile.pcos_type ?? 'not specified'}`,
    `Age: ${profile.age ?? 'not specified'}`,
    `Height: ${profile.height_cm ? profile.height_cm + ' cm' : 'not specified'}`,
    `Current weight: ${profile.current_weight_kg ? profile.current_weight_kg + ' kg' : 'not specified'}`,
    `Goal weight: ${profile.goal_weight_kg ? profile.goal_weight_kg + ' kg' : 'not specified (maintenance)'}`,
    `Goals: ${profile.goals && profile.goals.length > 0 ? profile.goals.join(', ') : 'not specified'}`,
  ]
  return lines.join('\n') + '\n\nGenerate daily macro targets for this user.'
}
```

**Key detail:** User ID (`user.id`) is NOT included in the prompt per GDPR guidance in AI-SPEC.md Section 1b. Only non-identifying clinical data enters the prompt.

### Pattern 5: Output Validation (validateTargets)

**What:** Type-check and range-check all 10 fields before writing to DB
**When to use:** Immediately after `JSON.parse()`. Throws on any violation — caller returns HTTP 500.

```typescript
// Source: 04-AI-SPEC.md Section 4b [CITED: .planning/phases/04-ai-targets/04-AI-SPEC.md]
interface AITargetsOutput {
  protein_g: number       // safe range: [40, 300]
  fiber_g: number         // safe range: [15, 80]
  gl_target: number       // safe range: [40, 200]
  added_sugar_g: number   // safe range: [10, 60]
  calorie_min: number     // safe range: [1200, 2500] — never below 1200 (critical safety floor)
  calorie_max: number     // safe range: [1400, 3000]
  pc_ratio_target: number // safe range: [0.15, 0.60]
  insulin_score: number   // safe range: [0, 100]
  narrative: string       // non-empty, <= 300 chars
  key_factors: string[]   // non-empty array
}

function assertRange(name: string, val: number, min: number, max: number): void {
  if (typeof val !== 'number' || isNaN(val) || val < min || val > max) {
    throw new Error(`${name} out of range: ${val} (expected ${min}–${max})`)
  }
}

function validateTargets(raw: unknown): AITargetsOutput {
  if (typeof raw !== 'object' || raw === null) throw new Error('Not an object')
  const r = raw as Record<string, unknown>

  assertRange('protein_g',       Number(r.protein_g),       40,   300)
  assertRange('fiber_g',         Number(r.fiber_g),         15,   80)
  assertRange('gl_target',       Number(r.gl_target),       40,   200)
  assertRange('added_sugar_g',   Number(r.added_sugar_g),   10,   60)
  assertRange('calorie_min',     Number(r.calorie_min),     1200, 2500)
  assertRange('calorie_max',     Number(r.calorie_max),     1400, 3000)
  assertRange('pc_ratio_target', Number(r.pc_ratio_target), 0.15, 0.60)
  assertRange('insulin_score',   Number(r.insulin_score),   0,    100)

  if (typeof r.narrative !== 'string' || r.narrative.trim().length === 0) {
    throw new Error('narrative missing or empty')
  }
  if (r.narrative.length > 300) throw new Error('narrative too long')
  if (!Array.isArray(r.key_factors) || r.key_factors.length === 0) {
    throw new Error('key_factors missing or empty')
  }

  // Forbidden content check — regex against raw response before parse
  // (applied to text string, not the parsed object — see Pattern 6)

  return r as unknown as AITargetsOutput
}
```

### Pattern 6: Forbidden Content Guardrail

**What:** Regex scan of raw Claude text response before JSON parse
**When to use:** After receiving `text` from Claude, before `JSON.parse()`

```typescript
// Source: 04-AI-SPEC.md Section 6 — Online Guardrails [CITED: .planning/phases/04-ai-targets/04-AI-SPEC.md]
const FORBIDDEN_PATTERNS = [
  /diagnos/i,       // "diagnose", "diagnosis", "diagnosed"
  /mg\/day/i,       // supplement dosage pattern
  /prescri/i,       // "prescribe", "prescription"
  /[Mm]etformin/,   // medication reference
  /dosage/i,        // general dosage advice
]

function checkForbiddenContent(text: string): void {
  for (const pattern of FORBIDDEN_PATTERNS) {
    if (pattern.test(text)) {
      throw new Error(`Forbidden content detected: ${pattern.source}`)
    }
  }
}
```

### Anti-Patterns to Avoid

- **Service role for user-owned data:** Do NOT use `SUPABASE_SERVICE_ROLE_KEY` for the `ai_daily_targets` insert. The RLS INSERT policy is already correct for authenticated users. Service role bypasses RLS — it's only needed when you must act on behalf of another user (as in `delete-account`). Using it here violates the principle of least privilege.
- **`JSON.parse()` without try/catch:** Synchronous throw will crash the handler and return a non-JSON 500. Always wrap in try/catch and return a structured error response.
- **Non-zero temperature:** Temperature > 0 causes JSON syntax variations in Claude's output that break parsing. Must be `0` for structured generation.
- **Multiple content blocks assumption:** `response.content[0]` may not be the only block in future API versions. Always check `.type === 'text'` before accessing `.text`.
- **User ID in prompt:** GDPR guidance in AI-SPEC.md explicitly forbids including `user.id` in the Claude prompt. Profile data is de-identified by design.
- **Logging full prompt/response:** AI-SPEC.md Section 1b: "Edge Function must not log the full Claude prompt/response to any monitoring system that stores PII." Only log `error_type` and a response excerpt on failures.
- **Blocking the event loop with synchronous operations:** All Supabase client calls and the Claude call are async — always `await`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| JWT verification | Custom JWT decode + signature check | `supabase.auth.getUser()` with user-scoped client | Handles expiry, signature, revocation — see `delete-account` pattern |
| Biological range enforcement | Ad-hoc if/else range checks | `validateTargets()` with `assertRange()` helper | Centralised, testable, extensible — throw semantics force callers to handle errors |
| JSON extraction from Claude | Regex to find `{...}` in prose | `temperature: 0` + system prompt instruction "return ONLY a JSON object, no prose" | Regex is brittle; deterministic prompting + `JSON.parse()` is reliable |
| Forbidden content detection | Full NLP classifier | Simple regex against 5 known patterns | Edge Function environment has no NLP libraries; regex covers the PCOS-specific risks enumerated in AI-SPEC.md |
| DB type safety | Manual cast of insert payload | `database.types.ts` `TablesInsert<'ai_daily_targets'>` type after regeneration | Auto-generated types from schema catch column name typos at compile time |

**Key insight:** The Edge Function has exactly one new responsibility that has no existing Bloom pattern: calling the Anthropic API. Everything else (JWT, DB, error response shape) follows patterns already in the codebase. The implementation is additive, not architectural.

## Common Pitfalls

### Pitfall 1: Missing CORS Headers Causes Silent 400 in Browser

**What goes wrong:** Browser preflight `OPTIONS` returns a non-200 with no CORS headers; the actual `POST` is blocked before it reaches the handler. Error appears in browser devtools as a CORS error, not as an HTTP 4xx from the function.
**Why it happens:** Supabase Edge Functions do not auto-inject CORS headers. The existing functions bypass this because `supabase.functions.invoke()` handles preflight at the Supabase client library level — but this is an implementation detail that can change.
**How to avoid:** Always add the `corsHeaders` block and handle `OPTIONS` at the top of `Deno.serve`. [ASSUMED: behaviour based on documented Supabase Edge Function CORS requirements — official docs recommend explicit CORS handling]
**Warning signs:** Network tab shows a `CORS` error on the preflight before any function log appears.

### Pitfall 2: `insulin_score` Column Not Yet in `database.types.ts`

**What goes wrong:** The insert payload includes `insulin_score` but TypeScript reports "Object literal may only specify known properties" because `database.types.ts` was generated before the migration.
**Why it happens:** `database.types.ts` is a snapshot. It does not auto-update when a new migration is applied. [VERIFIED: database.types.ts inspected — `ai_daily_targets.Row` does not contain `insulin_score`]
**How to avoid:** Wave 0 task must run `supabase gen types typescript --project-id nfyqateokdecjttimrhy > src/lib/database.types.ts` after applying migration 2. The planner must order this before any TypeScript that references the new column.
**Warning signs:** TypeScript compile error on the insert payload in `generate-targets/index.ts`.

### Pitfall 3: calorie_min > calorie_max from Claude

**What goes wrong:** Claude occasionally returns `calorie_min: 1800, calorie_max: 1700` — numerically valid individually but logically inverted.
**Why it happens:** Temperature 0 reduces but does not eliminate semantic errors in relative values.
**How to avoid:** Add a cross-field check in `validateTargets()`: `if (calorie_min >= calorie_max) throw new Error('calorie_min must be < calorie_max')`. Also add `>= 200` spread check: `if (calorie_max - calorie_min < 200) throw new Error('calorie range too narrow')`.
**Warning signs:** User-facing targets show a range like "1700–1700 kcal".

### Pitfall 4: Profile Row Exists but Key Fields are Null

**What goes wrong:** User completed onboarding but profile row has `pcos_type = null` or `age = null` (e.g., user skipped optional fields). Claude generates nonsensical targets because the prompt says "Age: not specified, PCOS type: not specified."
**Why it happens:** `profiles` table has all columns nullable. The trigger creates the row with only `id` populated; onboarding fills in the rest. A user who partially completes onboarding may have an incomplete profile.
**How to avoid:** Check that `pcos_type` is non-null (the one field that drives PCOS-specific targets). If null, return `HTTP 400 { error: "profile_required" }` per D-18. Missing optional fields (age, height, weight) fall back to "not specified" in the prompt — Claude handles this gracefully.
**Warning signs:** HTTP 400 with `error: "profile_required"` in logs despite user having a profile row.

### Pitfall 5: `esm.sh` Import Caching Stale SDK Version

**What goes wrong:** Deno caches the CDN import on first deploy. A security patch to `@anthropic-ai/sdk` is released but the function continues to use the cached version.
**Why it happens:** `https://esm.sh/@anthropic-ai/sdk` without a version pin resolves to "latest" at cache time, but Deno does not re-fetch after initial resolution. [ASSUMED: Deno CDN caching behaviour — consistent with documented Deno module caching]
**How to avoid:** Pin the version in the import URL: `https://esm.sh/@anthropic-ai/sdk@0.x.x` when the version is stable. For Phase 4, unversioned is acceptable — note in code comment that version should be pinned before production launch.
**Warning signs:** `npm view @anthropic-ai/sdk version` shows a newer version than what the function reports in its response.

### Pitfall 6: Narrative Exceeds 300 Characters

**What goes wrong:** `narrative text` column in DB has no length constraint. Claude may return a 3-sentence narrative at temperature 0 if the system prompt example is ambiguous.
**Why it happens:** "1–2 sentences" in the system prompt is advisory; Claude may interpret "briefly" differently.
**How to avoid:** (a) Include an explicit `narrative` field in the few-shot example showing exactly 2 sentences and a character count annotation, and (b) enforce `narrative.length <= 300` in `validateTargets()` with HTTP 500 on violation.
**Warning signs:** Dashboard shows truncated narrative text or layout overflow.

## System Prompt Design

### Full System Prompt (reference implementation)

```
You are a PCOS nutrition specialist AI. Your role is to generate daily macro targets 
that support insulin balance for a woman with PCOS.

STRICT PROHIBITIONS — you must NEVER:
- Provide a medical diagnosis or suggest the user has any condition beyond what is stated
- Recommend specific supplements, vitamins, or herbs with dosages (e.g., "take 2g inositol/day")
- Give advice about drug interactions or how food interacts with medications
- Suggest anything that requires evaluation by a healthcare provider
- Use deficit or restriction framing ("eat less", "reduce intake", "you are consuming too much")
- Make weight loss promises or claims

FRAMING RULES:
- Frame all targets as adequacy and support ("aim for at least", "supports stable energy")
- The Insulin Balance score reflects how well these targets support insulin sensitivity for this profile
- Targets are nutritional guidance, not medical advice
```

## Code Examples

### Complete Edge Function Structure

```typescript
// supabase/functions/generate-targets/index.ts
// Source: patterns from delete-account/index.ts + usda-search/index.ts + 04-AI-SPEC.md

import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'
import Anthropic from 'https://esm.sh/@anthropic-ai/sdk'

const PROMPT_VERSION = 1

const corsHeaders = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Headers': 'authorization, x-client-info, apikey, content-type',
}

// ── System Prompt ──────────────────────────────────────────────────────────
const SYSTEM_PROMPT = `...` // full text from System Prompt Design section above

// ── Profile → User Prompt ─────────────────────────────────────────────────
function buildUserPrompt(profile: Record<string, unknown>): string {
  return [
    `PCOS type: ${profile.pcos_type ?? 'not specified'}`,
    `Age: ${profile.age ?? 'not specified'}`,
    `Height: ${profile.height_cm ? profile.height_cm + ' cm' : 'not specified'}`,
    `Current weight: ${profile.current_weight_kg ? profile.current_weight_kg + ' kg' : 'not specified'}`,
    `Goal weight: ${profile.goal_weight_kg ? profile.goal_weight_kg + ' kg' : 'not specified (maintenance)'}`,
    `Goals: ${Array.isArray(profile.goals) && profile.goals.length > 0 ? (profile.goals as string[]).join(', ') : 'not specified'}`,
  ].join('\n') + '\n\nGenerate daily macro targets for this user.'
}

// ── Forbidden Content Guard ────────────────────────────────────────────────
const FORBIDDEN = [/diagnos/i, /mg\/day/i, /prescri/i, /[Mm]etformin/, /dosage/i]
function checkForbidden(text: string): void {
  for (const p of FORBIDDEN) {
    if (p.test(text)) throw new Error(`forbidden:${p.source}`)
  }
}

// ── Output Validation ─────────────────────────────────────────────────────
function assertRange(n: string, v: number, min: number, max: number): void {
  if (typeof v !== 'number' || isNaN(v) || v < min || v > max) {
    throw new Error(`${n}=${v} outside [${min},${max}]`)
  }
}

function validateTargets(raw: unknown) {
  if (typeof raw !== 'object' || raw === null) throw new Error('not_object')
  const r = raw as Record<string, unknown>
  assertRange('protein_g',       Number(r.protein_g),       40,   300)
  assertRange('fiber_g',         Number(r.fiber_g),         15,   80)
  assertRange('gl_target',       Number(r.gl_target),       40,   200)
  assertRange('added_sugar_g',   Number(r.added_sugar_g),   10,   60)
  assertRange('calorie_min',     Number(r.calorie_min),     1200, 2500)
  assertRange('calorie_max',     Number(r.calorie_max),     1400, 3000)
  assertRange('pc_ratio_target', Number(r.pc_ratio_target), 0.15, 0.60)
  assertRange('insulin_score',   Number(r.insulin_score),   0,    100)
  if (Number(r.calorie_min) >= Number(r.calorie_max)) throw new Error('calorie_min>=calorie_max')
  if (Number(r.calorie_max) - Number(r.calorie_min) < 200) throw new Error('calorie_range_too_narrow')
  if (typeof r.narrative !== 'string' || r.narrative.trim().length === 0) throw new Error('narrative_empty')
  if (r.narrative.length > 300) throw new Error('narrative_too_long')
  if (!Array.isArray(r.key_factors) || r.key_factors.length === 0) throw new Error('key_factors_empty')
  return r
}

// ── Handler ───────────────────────────────────────────────────────────────
const anthropic = new Anthropic({ apiKey: Deno.env.get('ANTHROPIC_API_KEY')! })

Deno.serve(async (req) => {
  if (req.method === 'OPTIONS') {
    return new Response('ok', { headers: corsHeaders })
  }

  const jsonHeaders = { ...corsHeaders, 'Content-Type': 'application/json' }

  try {
    // 1. Verify JWT
    const authHeader = req.headers.get('Authorization')
    if (!authHeader) return new Response(JSON.stringify({ error: 'unauthorized' }), { status: 401, headers: jsonHeaders })

    const supabaseUser = createClient(
      Deno.env.get('SUPABASE_URL')!,
      Deno.env.get('SUPABASE_ANON_KEY')!,
      { global: { headers: { Authorization: authHeader } } }
    )
    const { data: { user }, error: authError } = await supabaseUser.auth.getUser()
    if (authError || !user) return new Response(JSON.stringify({ error: 'unauthorized' }), { status: 401, headers: jsonHeaders })

    // 2. Fetch profile
    const { data: profile, error: profileError } = await supabaseUser
      .from('profiles')
      .select('pcos_type, goals, age, height_cm, current_weight_kg, goal_weight_kg')
      .eq('id', user.id)
      .single()

    if (profileError || !profile || !profile.pcos_type) {
      return new Response(JSON.stringify({ error: 'profile_required' }), { status: 400, headers: jsonHeaders })
    }

    // 3. Call Claude
    const message = await anthropic.messages.create({
      model: 'claude-sonnet-4-6',
      max_tokens: 512,
      temperature: 0,
      system: SYSTEM_PROMPT,
      messages: [{ role: 'user', content: buildUserPrompt(profile) }],
    })

    const text = message.content[0].type === 'text' ? message.content[0].text : ''
    if (!text) throw new Error('empty_response')

    // 4. Guardrail + parse + validate
    checkForbidden(text)
    let parsed: unknown
    try { parsed = JSON.parse(text) } catch { throw new Error('json_parse_failed') }
    const targets = validateTargets(parsed)

    // 5. Insert to DB
    const generated_at = new Date().toISOString()
    const { error: insertError } = await supabaseUser.from('ai_daily_targets').insert({
      user_id: user.id,
      protein_g:           Number(targets.protein_g),
      fiber_g:             Number(targets.fiber_g),
      gl_target:           Number(targets.gl_target),
      added_sugar_g:       Number(targets.added_sugar_g),
      calorie_min:         Number(targets.calorie_min),
      calorie_max:         Number(targets.calorie_max),
      pc_ratio_target:     Number(targets.pc_ratio_target),
      insulin_score:       Number(targets.insulin_score),
      insulin_score_basis: { key_factors: targets.key_factors },
      narrative:           String(targets.narrative),
      prompt_version:      PROMPT_VERSION,
      generated_at,
    })
    if (insertError) throw new Error(`insert_failed: ${insertError.message}`)

    // 6. Return response (note: generated_at in response, not insulin_score_basis or key_factors)
    return new Response(JSON.stringify({
      protein_g:        Number(targets.protein_g),
      fiber_g:          Number(targets.fiber_g),
      gl_target:        Number(targets.gl_target),
      added_sugar_g:    Number(targets.added_sugar_g),
      calorie_min:      Number(targets.calorie_min),
      calorie_max:      Number(targets.calorie_max),
      pc_ratio_target:  Number(targets.pc_ratio_target),
      insulin_score:    Number(targets.insulin_score),
      narrative:        String(targets.narrative),
      generated_at,
    }), { headers: jsonHeaders })

  } catch (err) {
    const msg = err instanceof Error ? err.message : String(err)
    console.error('generate-targets error:', msg)
    return new Response(JSON.stringify({ error: 'generation_failed', message: msg }), { status: 500, headers: jsonHeaders })
  }
})
```
