<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL / navigation → guard | Users can type any URL directly; guards enforce auth state and profile completion |
| localStorage (onboardingStore) → RequireProfile | Step index read from localStorage; only used to determine WHICH onboarding step to resume, not to grant access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | Route guard bypass via direct URL | mitigate | RequireAuth and RequireProfile evaluate auth state from AuthContext (server-validated JWT), not from localStorage. Guard checks DB (useProfile) for profile completion — not just localStorage onboarding step. |
| T-04-02 | Elevation of Privilege | Onboarding skip via localStorage manipulation | mitigate | RequireProfile checks profile.pcos_type from the database, not from localStorage. Tampering with onboardingStore.currentStep only affects which step is shown — cannot grant access to the main app. |
| T-04-03 | Information Disclosure | Profile data exposed via useProfile | accept | Profile data is fetched only for the authenticated user (RLS enforces this). No cross-user data access possible. |
| T-04-SC | Tampering | npm package installs | mitigate | No new packages in this plan. All previously audited. |
</threat_model>
