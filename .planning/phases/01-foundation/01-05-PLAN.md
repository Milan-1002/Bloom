<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → delete-account Edge Function | Caller JWT verified by Supabase anon client before admin delete; service_role key never leaves the Edge Function |
| Browser → PWA service worker | SW intercepts network requests; only Supabase CDN and built assets are cached |
| localStorage (theme) → applyTheme | Theme values constrained to known palette set in loadTheme() |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | delete-account without confirmation | mitigate | ProfileScreen requires user to type "DELETE" in a confirmation field before invoking Edge Function. No accidental deletions. |
| T-05-02 | Elevation of Privilege | delete-account unauthenticated call | mitigate | Edge Function reads Authorization header; returns 401 if missing or if getUser() fails. Admin client only created after user identity is verified. |
| T-05-03 | Information Disclosure | SUPABASE_SERVICE_ROLE_KEY in client bundle | mitigate | Key is stored only in Supabase Edge Function secrets (Deno.env). Never appears in Vite env files. Key is not accessible from browser JS. |
| T-05-04 | Tampering | Onboarding step skip via direct URL | mitigate | RequireProfile checks profile.pcos_type from DB (not localStorage). Direct navigation to /home before onboarding completes triggers redirect to /onboarding/{currentStep}. |
| T-05-05 | Denial of Service | PWA service worker caching stale auth | mitigate | SW uses NetworkFirst for Supabase URLs (RESEARCH.md line 979). Auth responses are not served from cache. |
| T-05-SC | Tampering | npm/supabase package installs | mitigate | No new npm packages in this plan. supabase Edge Function imports from esm.sh (pinned version @2). |
</threat_model>
